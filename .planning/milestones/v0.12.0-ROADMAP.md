# Roadmap: v0.12.0 Per-Grain Metric Aggregation (Phases 69-71)

**Milestone goal:** close TECH-DEBT #35 — compute each metric at its own grain,
Snowflake-style, so multi-grain queries return correct numbers instead of raising
a fan-trap error.

Requirements: `.planning/milestones/v0.12.0-REQUIREMENTS.md` (GRAIN-01..08,
VER-01..04, DOC-01..03, REL-01).

## Design summary

The generated query stays base-anchored **wherever that is correct**. The
per-grain path is entered only for the shapes v0.11.0 rejects, so single-grain
SQL is byte-identical to v0.11.0.

```
                     ┌── plan_grains(def, dims, metrics) ──┐
  expand()  ─────────┤                                     ├── None  → existing base-anchored path
                     └── Some(plan) when a base-anchored ───┘         (+ full fan-trap fence)
                         FROM would inflate AND the query
                         is per-grain eligible
                                    │
                                    ▼
                     WITH __sv_grain_0 AS (   -- anchored FROM <metric grain table>
                              SELECT <dims>, <metrics at this grain> ... GROUP BY <dims>
                          ),
                          __sv_grain_1 AS ( ... )
                     SELECT COALESCE(g0.d, g1.d) AS "<dim>", g0.m0, g1.m1, <derived over both>
                     FROM __sv_grain_0
                     FULL OUTER JOIN __sv_grain_1 ON <null-safe dim equality>
```

**Eligibility** (all must hold, else the v0.11.0 error stands): no window metric,
no *active* semi-additive metric, no role-playing/`USING` resolution in play, and
every queried dimension reachable from every metric grain through non-fanning
edges (a dimension below a metric's grain remains a `FanTrap` error).

## Phases

### Phase 69: Per-grain aggregation core

**Goal:** multi-grain **aggregate** metric queries (base + single-grain derived)
are answered per-grain. GRAIN-01/02/03/05/06/07/08.
**Depends on:** —

- [x] 69-01 — `src/expand/per_grain.rs`: grain partitioning + routing predicate
  (`plan_grains`), anchored join resolution, CTE + `FULL OUTER JOIN` emission;
  `check_fan_traps` gains a `per_grain` mode that suppresses exactly the three
  checks per-grain supersedes (root-grain, metric×metric, intra-metric span)
  while keeping metric×dimension live.
- [x] 69-02 — Test wave: `src/expand/tests_per_grain.rs` (unit / emission),
  `test/sql/phase69_per_grain.test` (numeric, via the full extension path),
  `tests/star_schema_proptest.rs` invariant strengthened (VER-03).

### Phase 70: Multi-grain derived metrics

**Goal:** a derived metric whose components span grains is decomposed into
per-grain component columns and re-assembled in the outer SELECT. GRAIN-04.
**Depends on:** Phase 69

- [x] 70-01 — Component decomposition (`inline_references` over per-grain column
  refs), depth/cycle reuse of the existing derived-metric resolution, emission +
